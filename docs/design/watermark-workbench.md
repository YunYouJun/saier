# 快速水印工作台与 PSD 互通

> 状态：P15-01 原尺寸图片工作流已实现；P15-02～06 待实施。更新于 2026-09-27。
> 对应 [Roadmap P15](./roadmap#p15)。按下面的任务顺序逐项实施、验收，不把整份计划作为一次重构。

## 产品目标

在 Saier 内完成「拖入画作 → 套用个人水印 → 适当编辑 → 下载」，并能切换到完整绘画界面继续创作。快速模式与绘画模式共享同一个文档、图层、历史和导出管线，只改变工具展示，不创建第二套编辑器。

桌面优先，以熟悉的图层选择、拖动、变换、快捷键和撤销建立接近 Photoshop 的日常操作体验。首版围绕图片与水印编辑，不包含 Photoshop 的完整文字排版、调整图层、智能对象、滤镜和印刷色彩工作流。

## 首版交互

### 进入与导入

- `/` 保持主入口（遵循 D12），欢迎区域增加「给图片加水印」；进入后使用简化工具栏与水印属性面板。
- 首次拖入／粘贴 PNG 或 JPEG：校正图片方向后，按实际图像像素新建文档，自动适配视口，原图层默认防误编辑。不得把「适配视口」变成缩小原始像素。
- 在已有文档中，区分「打开为新文档」和「置入为图层」；添加水印按钮进入图片置入或文字创建。失败的解码不留下空文档／半个图层。
- 导入为本地操作；云端同步沿用用户主动保存流程。超出支持的尺寸／像素预算时提供原因和显式缩小选项，不静默降采样。
- 快速模式切换到完整绘画模式时保留文档 ID、选中层和历史；房间 Activity 不使用这套导入入口。

### 水印与常用编辑

- 图片水印：透明 PNG、原始素材保留、缩放／旋转／翻转、透明度和层级。
- 文字水印：内容、字体、字号、颜色、描边、透明度；双击进入文字编辑。首版支持普通横排与手动换行，富文本、路径文字另行评估。
- 单击选择、拖动移动；角点默认保持比例，沿用当前 Shift 临时自由缩放规则；Shift 旋转吸附到 15°。
- 九宫格定位、边距、画布边缘／中心吸附；吸附阈值按屏幕像素计算，最终位置写入文档坐标。Alt 临时关闭吸附。
- 支持多个水印、复制、删除、显隐和透明度调整；首版单对象操作，多选联合变换后置。
- 原图的防误编辑是独立的编辑锁定语义，不能用当前 `lockAlpha` 代替。快速模式还须防止画笔／删除快捷键绕过这一约束。

### 快捷键与操作事务

| 操作                             | 计划行为                                                      |
| -------------------------------- | ------------------------------------------------------------- |
| `V`                              | 选择／移动图片或水印；选中时直接显示变换框，保留现有 `S` 别名 |
| `T`                              | 添加／编辑文字水印                                            |
| `Space` + 拖动                   | 临时平移视图，松开恢复之前的工具                              |
| 方向键 / `Shift` + 方向键        | 文档坐标微调 1 / 10 px                                        |
| `Enter` / `Esc`                  | 提交／取消当前变换；文字编辑时按编辑器语义处理                |
| `Delete` / `Backspace`           | 删除选中可编辑水印；输入框聚焦时正常编辑文字                  |
| `Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z` | 撤销／重做，按钮与键盘调用相同命令                            |
| 复制、导出、适配视图             | 提供可见按钮和菜单，快捷键经浏览器冲突验证后再启用            |

Web 不把 `Ctrl/Cmd+T` 作为必需的变换入口，它与浏览器新建标签页冲突；桌面 adapter 可以提供平台快捷键。保留现有 `H` 重置视图等绑定，避免无提示重映射。

命令优先级固定为「模态框／文本输入与 IME → 活动文档 → 画布工具」。失焦、切换文档、关闭面板时释放 Space／修饰键状态。输入框、contenteditable 和中文输入法组合输入期间不触发画布快捷键。

一次拖动、一次滑块拖动、一次文字编辑提交或一段连续方向键微调只产生一条历史记录；Esc 回到事务开始状态。点击下载／保存前先提交有效编辑，取消导出不修改画作。

## 架构与数据边界

遵循 D2、D7、D12、D15：文档像素不受缩放／DPR 影响；Vue 只展示状态；像素快照继续保证工程打开结果。

| 层                      | 职责                                                                       |
| ----------------------- | -------------------------------------------------------------------------- |
| `@saier/core`           | 文档图层、编辑锁定、可编辑来源描述、历史命令、格式校验／迁移、PSD 数据适配 |
| `saier` / `@saier/pixi` | 图片解码与文字栅格化接线、图层呈现、命中检测、变换框、吸附参考线           |
| `@saier/vue`            | 可复用变换与属性控件，调用 controller／runtime 命令                        |
| `site`                  | 快速模式、水印预设、打开／导出流程、文件 adapter 与兼容性提示              |

### 可编辑来源与像素快照

不立即把现有 raster engine 改写成完整矢量排版引擎。计划为栅格层关联可编辑来源：图片引用内嵌原始素材，文字保存内容、字体标识、字号、填充和描边等属性。变换、显隐、透明度、顺序只保留在现有图层模型，避免两份真相。

- 来源信息用于再次编辑／重新生成图层；已保存的像素快照用于可靠打开和预览。打开工程不能自动重排文字而改变外观。
- 文字栅格化通过注入的 renderer 完成，DOM／字体加载放在浏览器适配层，core 不依赖 Vue 或 Pixi。
- 每次文字属性更新原子提交来源与派生像素；异步字体加载或栅格化使用文档／图层修订号，丢弃已经过期的结果。撤销同时恢复来源、像素和变换。
- 字体缺失时保留快照，并在再次编辑前展示替代字体选择；首版不自动打包系统字体，不承诺跨机器重新排版逐像素一致。
- 对来源管理的水印层直接绘画前，提供可撤销的「转为普通像素层」动作，避免下一次修改文字覆盖已经画出的内容。
- 个人预设保存素材、样式、锚点、相对边距和相对尺寸，实例化后属于独立图层；修改预设不追溯修改旧作品。PNG 等二进制素材放 IndexedDB，避免大量 base64 塞入 localStorage。

### 智能水印布局与保护区域

2026-09-27 需求补充：支持「避开脸部等主要部位」的规则，纳入 P15-04a。这里的脸部包括绘画角色、二次元、兽设和风格化人物，采用多模态语义分析作为主要识别路径，不假定普通真人脸检测器能够覆盖。AI 识别保护区域、解释规则并提出位置；Saier 使用原始水印图层进行确定性合成，继续保留图层编辑和撤销能力。**水印处理明确不调用生图／改图模型，不用生成结果替换原画或水印素材。**

- 自然语言与可见规则控件对应，例如「使用我的白色签名，优先右下角，避开脸部，透明度 25%」。规则落到受校验的结构化参数；AI 输出不能直接成为任意可执行命令。
- 保护区域统一用文档坐标的矩形／蒙版表示，记录来源（模型建议／用户标注）、修订号和不确定性说明。区域可以是角色脸、眼睛、标题、已有签名、重要道具等。角色脸区域加保护边距，用户可显示、增补、删除和调整区域；模型自报的置信分数不视为经过校准的准确率。
- 「避开脸部／手动保护区域」作为硬约束，主体重叠、背景繁杂度、可读性和位置偏好作为可配置优先级。检测不到脸不能被解释为确定没有脸。
- 布局器生成多个候选位置，使用水印变换后的实际覆盖范围检查保护区域与画布边界。没有满足硬约束的位置时保留当前布局并提示调整尺寸／规则，不能静默降低保护要求。
- 首先提供手动保护区域和确定性的候选布局，再接多模态语义分析。MediaPipe 一类真人脸检测器仅作为以后可选的照片辅助能力，不作为绘画角色脸识别的默认方案或前置依赖。
- 分析通道由统一 provider 契约隔离：云乐坊 AI Runtime 与本机 Codex 返回相同结构的结果。选择启用时明确实际模型服务商与图像发送目的地；默认不自动发送整份工程或原尺寸作品。产品云端入口沿用云乐坊账号、统一 AI Runtime 与 AI 点账本，浏览器不直连模型绕过计费，也不放置平台凭证。CloudBase 只是 Runtime 可选择的下游模型通道之一。
- 现有 `pictionary-ai-remix.cjs` 是 Activity 图片生成能力，不能直接作为主体定位 API；新建工作台分析接口，复用鉴权与用量管理思路，保持与房间 Activity 的数据隔离。
- 缓存按图像内容、分析尺寸、模型／规则版本区分。异步结果带文档 ID 与修订号；切换文档或画作变化后丢弃旧建议，缩略图分析坐标需正确映射回文档像素。
- 展示候选布局和保护区域，用户应用后产生一次可撤销的图层操作。分析失败仍可手动放置水印；不承诺自动检测永远正确。

技术调研入口：[Gemini 图像理解](https://ai.google.dev/gemini-api/docs/image-understanding) 提供对象检测／分割接口说明；[OpenAI 视觉限制](https://developers.openai.com/api/docs/guides/images-vision#limitations) 明确提示定位和识别可能出错。多模态模型的语义理解并不自动保证像素级定位准确，需用真实画作评测、展示保护区并允许校正，不能仅凭模型名称承诺效果。

#### 分析请求与确定性合成契约

1. Saier 生成方向已校正的画作分析快照，记录 `documentId`、修订号、内容哈希、分析图尺寸和坐标映射；请求只携带这张快照与规则。图片内文字作为画作内容，不作为执行指令。
2. 分析端返回受 JSON Schema 约束的保护区域：语义标签、相对分析图的归一化边界框、保护优先级、不确定性说明，以及可选的位置建议。首版使用带边距的矩形；多边形／精细蒙版须经过独立定位验证后再开放。
3. Saier 校验版本、有限数值、边界范围、区域数量、文档修订号和坐标映射。Schema 合法只代表结构正确，不代表区域识别正确；不接受可执行脚本、任意文件路径或新的生成图像作为分析结果。
4. 布局器根据保护区域、现有水印尺寸／透明轮廓和用户规则计算候选位置，检查旋转后覆盖范围与重叠。云端与 Codex provider 共用这一布局器，测试采用固定区域输入以保证相同输入得到相同结果。
5. 预览显示保护区域和候选位置；应用只更改水印图层的变换／透明度等属性。原画像素保持不变，PNG/JPEG 仍由现有确定性合成管线导出，应用可撤销。

#### 可选的本机 Codex 分析通道

- 本机已核对 `codex-cli 0.154.0`：`codex exec` 支持图片输入、`--output-schema` 和 `--output-last-message`；可作为短任务原型。正式交互可使用 [Codex App Server](https://learn.chatgpt.com/docs/app-server#turns) 的 `localImage`、`outputSchema`、进度事件与取消接口。协议能力按实际安装版本检测，不要求用户升级到未经验证的版本。
- Electron 优先通过主进程的受限 IPC 调用本地分析适配器；纯 Web 可选用户主动连接的本地 companion。网页不能直接启动本机 CLI，也不直接暴露通用命令执行接口。
- companion 只监听本机，通过明确配对、来源校验和会话凭证接收限定格式的分析请求；传入图片字节／请求 ID，不让网页指定任意磁盘路径、命令或工作目录。
- 每个分析任务使用隔离的临时输入与最小读取范围；不加载无关仓库上下文，不授予原画／工程写入权限，禁用无关工具、插件与生图能力。只读沙箱不等同于禁止全部工具，实施时须单独验证工具限制和实际权限。任务结束清理输入和结果临时文件。
- 本机运行 Codex 不等于离线推理。若当前 provider 使用云端模型，图像仍发送到对应模型服务并受该账号／provider 的用量限制；完全离线的视觉模型是另一条需独立评测的 provider，不作为本地 Codex 接入的默认承诺。
- 首版接入本机 Codex **运行时**。在已打开的 Codex 桌面聊天中自动显示任务、继续对话并回填结果，是独立的桌面 UI 集成，当前未验证；不把本对话可用的线程工具当作 Saier 网站普遍可调用的接口。
- 验收覆盖 Codex 未安装／未登录、模型不支持图片、输出不合法、取消／超时／限额、旧结果回流、恶意图片文字和本地桥接来源隔离；故障时保留手动编辑能力。

#### PSD 素材预设与提示词分工

- **素材包／结构化预设是事实来源**：原始 RGBA、水印角色、混合模式、图层透明度、相对尺度、配色范围、保护边距和版本；原 PSD 布局只作参考，新图必须重新定位。
- **版本化提示词负责语义分析**：识别绘画角色脸与重要区域，提出有限的资产角色、位置、颜色和透明度；输出 JSON，不生成或改写画作／署名像素。
- **确定性工具负责执行与验收**：颜色调整保留原始 alpha，应用时再乘图层透明度；保护区碰撞校验、组合图层、导出、快照修订检查不交给模型自由发挥。
- **Skill 是可选的调用外壳**：重复批处理工作流稳定后再封装“选择预设 → 分析 → 预览 → 合成 → 验证”。不把私有素材放进公开 Skill，不用提示词替代数值预设或代码验证。
- 本次参考 PSD 包含三段缎带、全画面边框／署名、两处签名，以及叠加／线性光纹理。噪声图层已有针对旧画角色脸的透明洞，不能当作通用保护区域。原始签名图层含外发光／描边参数，提取 PNG 保留栅格像素，效果参数单独保存，不能声称 Photoshop 外观完整复现。
- 个人素材输出在本机 Downloads，没有加入 `site/public` 或上传云端。实验页现支持单张 PNG 及 `saier.watermark-preset` v1 内嵌 PNG 预设包；提供多素材布局、颜色／透明度与位置调整，仍未接入预设云同步。

## PSD 兼容等级

继续评估和复用已经安装的 `ag-psd`，先限定 **RGB、8 bit/channel、普通 PSD**。支持范围按 fixture 与目标应用实测扩展，不能由依赖库的 API 名称推导出产品兼容承诺。

### A：读取合成预览，给 PSD 作品加水印

- 读取 PSD 保存时携带的合成图，作为一张原图进入水印流程；UI 明示「作为合成图片打开」，不显示为完整分层导入。
- 合成图不存在或无法解码时明确失败，并提示从 Photoshop 导出 PNG 或使用后续受限分层导入；不把部分图层拼接伪装成原图。
- 使用库提供的合成图不代表实现了图层效果、ICC 转换或 Photoshop 合成器。初期仅对已验证的 RGB/sRGB 样例宣称外观一致，其他配置展示限制或拒绝。

### B：基础分层导入

- 保留位图层、顺序、名称、位置、显隐、透明度，以及经过验证的分组和混合模式。
- 为组级显隐／透明度、pass-through、蒙版、剪贴、文字、智能对象、调整层和图层效果建立逐项检测。
- 不支持的内容在打开前给出兼容性报告，允许改用合成图。只有测试确认的内容才进入分层编辑；现有「不支持混合模式转 normal」行为不能无提示进入正式 UI。
- 文字、形状或智能对象只能在确有可用位图且效果可解释时作为栅格层导入；不承诺文字可编辑或智能对象可还原。复杂组级效果不能简单对子层乘透明度来替代。

### C：基础分层 PSD 导出

- 首版优先导出「原图 + 独立水印」这些普通栅格层，并写入正确的合成预览。
- 变换烘焙到各层导出像素和偏移，文字水印按独立像素层输出；它们在 Photoshop 中仍可独立移动／调整透明度，文字内容编辑留在原生工程。
- 图层透明度／混合模式只应用一次，正确处理预乘／直通 alpha；旋转层的边界、裁切和透明边缘必须有像素回归。
- 对当前编辑器里的复杂蒙版／剪贴／不支持合成模式，提前列出影响；提供明确的合并导出选择，不静默改变外观。
- 不覆盖来源 PSD；导出新文件。保留未解释的 PSD 数据块并不能保证往返保真。

CMYK、16/32 bit、PSB、可编辑 PSD 文字、智能对象往返和高级效果不属于本轮。原生格式与 PSD 是互补关系：前者保存 Saier 编辑语义，后者交付明确的交换子集。

### 解析与验证要求

- 在解码像素前检查文件头、文档／图层边界、图层数与累计像素内存预算；用安装版本已提供的 `useRawData` / `totalMemoryLimit` 验证受限解析路径。
- 限制针对所有图层的累计资源，不能只检查文档宽高或压缩文件大小；错误不能破坏当前已打开文档。
- PSD 解码按需加载并放到可取消的 Worker；这不等于把绘画热路径搬进 Worker。
- 同一库写入再读取只是基础检查。增加合法来源的 Photoshop 保存样例，验证图层属性和合成结果；导出文件需在真实 Photoshop 中打开验收。没有目标软件验证时只能标记为「基础互通测试通过」，不能标记「Photoshop 兼容已验证」。

外部依据（核对于 2026-09-27）：[Adobe PSD 文件规范](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/)；[ag-psd 官方说明](https://github.com/Agamnentzar/ag-psd#limitations)。库负责文件读写，修改内容后的文字位图和合成图仍需应用生成；其文字与部分颜色模式支持有限。

### PSD 效果校正（2026-09-28）

维护者确认需要主体十字覆盖，上一版边缘布局不符合要求。新规则把横缎带与长纵缎带相交于主体，心形主图标和 `FOR DISPLAY ONLY` 放在主体轮廓内，满屏小字与细纹理覆盖全画布，仅新识别的脸部等区域留空。

- 直接检查参考 PSD：三段缎带均为正常混合、图层不透明度 100%，无 `effects`、蒙版或非默认 Blend If；半透明来自原始 PNG alpha。参考中的模糊已烘焙在「背景 拷贝」，不是缎带上的图层样式。
- 预设新增 `backdropBlur`（画布短边比例，限制 0–0.03）。客户端先从未修改的原图生成局部模糊底，再画所有缎带，避免交叉处后画的模糊抹掉前一条缎带。参考未保留模糊参数，0.013 是外观复刻值，不承诺像素级复原 Photoshop 操作。
- `blendMode` 支持 normal、overlay、linear-light。细纹理使用叠加 105/255，小字纹样使用线性光 100%；线性光通过分行像素合成实现，因为 Canvas 没有同名原生模式。混合模式语义参考 [Adobe 文档](https://helpx.adobe.com/ee/photoshop/desktop/repair-retouch/adjust-light-tone/blending-mode-descriptions.html)。
- `repeated-watermark` / `micro-texture` 的 width 为循环单元宽度，原点固定、覆盖全画布；`frame` 单独保留四角并延展边线。标题、署名从边框拆出，避免横幅画作拉伸文字。
- 所有效果合成后恢复保护区及短边 2% 边距内的原始 RGBA，包括透明像素。成品仍是 4800 × 4300，原图文件不变。此次复用云端已有识别并人工补两个小玩偶脸，按参考修正布局，没有再次收费调用模型；不能把修正版称为新模型自动布局验收。

### 主色与脸部锚点构图（v3，v4 已调整配色与爱心尺寸）

维护者补充：边框和底部署名应使用画面主色系深色；爱心位于主脸左下方；十字向上调整并避脸。这些偏好抽象为 `SUBJECT_CROSS_RULES`，预设打包、Codex 分析与云端分析复用同一份规则；默认规则相同时，提示词不重复附带整段预设规则。

- 从主体服装和道具的大面积颜色取主色，排除白背景、肤色、孤立点缀。边框与底部署名统一使用该色系深色，保留 alpha；两类素材在预设中允许换色。爱心、纹理和缎带不随边框一起压暗。
- 爱心用主脸相对位置定位：中心偏左、下巴下方，优先肩部或上胸衣服；宽度从脸宽的 0.65–0.9 倍开始。拥挤时先缩小、微移，不固定到某个画布百分比。
- 横带优先上腰／躯干下半部，纵带位于脸侧并向上延伸；联合平移和缩放，保证十字在主体内相交。整段带与模糊底均应离开脸部安全区，不能仅依靠最终挖洞来掩盖穿脸布局。
- 输出前检查同色系深色、脸部锚点、交叉位置、完整保护、文字可读性、边框内边距及纹理完整性。本次示例沿用已有识别并人工修正；新提示词另需跨画作效果评估。

### 工作台 PSD 导出与 Krita 互通（2026-09-28）

工作台新增「下载分层 PSD」，复用 `ag-psd` 31.0.2 写出 RGB、8 位、RLE 压缩的普通 PSD。导出器独立于 Vue 与 Painter，使用当前原图、已确认的布局与保护区域，不调用 AI。

- 文字和图标都是像素水印，支持移动、缩放、调色和透明度；不承诺直接编辑文字内容、智能对象或实时样式。正式画板通用 PSD 保存、复杂 PSD 往返及 Photoshop 验收仍不在此交付范围。

实际用本机 Krita 5.3.2 读取 4800×4300 样例 PSD，并另存 PNG 与 KRA：14 个像素图层（原图 + 9 个水印 + 4 个柔化层）和 5 个透明度蒙版保留，细纹理为 overlay / 105，重复小字为 linear light / 255。Krita 重合成 PNG 相对网页 v4 PNG 的 RGBA 平均绝对差 0.0764、最大差 3（0–255），没有大于 10 的差异像素；因此承诺此样例视觉近似一致，不宣称跨合成器逐像素相同。PSD 为 133251079 字节，原素材没有公开上传。能力边界参见 [Krita 官方 PSD 文档](https://docs.krita.org/en/general_concepts/file_formats/file_psd.html)。

### 主画板插件面板（2026-09-28）

水印工作流现可从主入口 `/` 的「插件 → 水印」开启，作为现有面板系统的扩展。桌面支持拖动、折叠及合并标签，手机使用底部面板；本次没有新增路由。`/watermark-lab` 保留旧实验入口兼容。

- `editor-plugins/registry.ts` 注册可信内置插件的 ID、标题、图标、动态组件。主界面通过 `plugin:<id>` 动态插槽注入桌面／手机 Shell，开关单独保存在本机。后续插件优先贡献面板及文档适配器，不复制页面或另起 Painter。本接口不执行用户上传的 JavaScript。
- 水印面板可直接读取当前画布、导入图片／预设或打开已有工作文件，编辑 AI 服务和布局规则，再在同一个 Painter 内创建水印文档标签。已是水印文档时读取未合成的原图和当前布局，避免重复叠加。AI 按钮仅分析，应用布局需要明确点击；不会在开启面板时收费调用。
- `useWatermarkDocuments` 按文档 ID 持有 `WatermarkWorkspace` 适配器；主画布、原生选择变换与历史共用，不创建第二个画布工作台。关闭插件仅关闭面板，已打开的文档及编辑仍保留；重新开启可继续调整。关闭文档才释放对应适配器。切回绘画标签恢复原图层与绘画面板。主画布与 Activity 工作区通过 Teleport 保持节点身份，切换桌面／手机外壳不再重建 canvas。
- 保存命令在水印文档中导出包含素材、保护区和布局的工作文件；PNG／PSD 仍由原有全尺寸合成器导出，保留混合模式和局部背景柔化。水印文档暂不进入普通工程草稿、绘画云同步或协作房间流程，防止把仅用于交互的代理图层误存成完整作品。界面明确提醒离开前保存工作文件，尚未提供水印作品自动恢复。
- 绘画／滤镜／普通图层增删命令在水印文档中受限，水印从专用图层列表和属性面板调整；切回绘画文档可继续绘制。打开大文件和导出期间暂时锁定文档切换，防止异步导入落到其他画布。
- AI 服务选择和用户规则可在本机记忆；配对凭据、原图和私有预设不写入这些 localStorage 配置。关闭面板或切换文档取消等待中的分析。云端已经提交的请求仍遵循统一 Runtime 的结算规则。

此接入沿用程序化预设适配器和 v1 工作文件，尚未升级通用 `saier.project` 文档协议。注册新插件仍需代码接入；面板内的素材、AI 规则与逐层参数可以由用户配置。

## 自定义素材与 Drive 私有库

主界面「插件 → 水印 → 素材、布局与 AI 配置 → 我的水印」支持导入 PNG / JPEG / WebP，
选择素材用途及是否随画面调整颜色。单文件上限 25 MB、最长边 8192px，每套最多 12 个素材，
合计 3200 万像素。新增素材保留已有布局；所有图片转换为内嵌 PNG，随预设与工作文件保存。

「Drive 私有素材库」复用云乐坊登录及 `@yunlefun/assets` 协议。读取、搜索、分页、选用和明确
上传均走独立 `saier-assets-api` 云函数；文件直接通过短期签名上传至统一私有存储。不会自动
上传画作，也不会把素材加入公开预设。角色、混合效果及布局继续由 Saier 预设管理。

服务端只接受网关 UID，Drive 再执行 owner / tenant / space 隔离。客户端每次请求检查真实
会话，换号立即清除云端列表；已明确选入当前本地文档的图片是文档内容，不会在退出时删除。
下载校验字节数与 SHA-256，不持久化签名 URL。完成上传失败可以单独重试确认。
